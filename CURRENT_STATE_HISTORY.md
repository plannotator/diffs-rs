## What we are building

The product is a read-only diff viewer for an existing terminal window.
Pierre supplies the presentation reference: clear split and unified views, readable source, useful syntax colors, and precise changed-word emphasis.
The target includes the exact large patches cached by DiffsHub, including the approximately 678 MiB Linux patch.

The priority order is correct diff content, readable presentation, stable interaction, then measured speed and memory use.
A performance change cannot omit source, invent syntax context, or silently weaken the display.
Rust is the implementation choice, not evidence that the viewer outperforms another product.

The viewer uses Ratatui and Crossterm. It does not use OpenTUI, React, or a browser renderer.
The current product reads existing patches. It does not yet generate comparisons directly from two files or Git revisions.

## What works now

- Patch-file and stdin input, including a pipe from Git.
- Split and unified layouts, dark and light themes, wrapping, and line-number visibility.
- Syntax colors and word-level emphasis, with separate old/new syntax state.
- Line and page movement, first/last source movement, adjacent-file movement, and hunk movement.
- Mouse-wheel vertical scrolling, a reading cursor, and keyboard horizontal scrolling.
- Source, side, and text-position preservation through width, wrap, and layout changes in the covered process tests.
- Incremental availability of complete files while later input loads.
- Continued access to earlier files after a later input failure, with an explicit incomplete state.
- Safe literal display of covered unsafe text cases and terminal restoration on covered exit and interruption paths.

At 120 columns or more, automatic layout uses split view. Narrower windows use unified view.
The minimum usable size is 40 columns by 10 rows.
The current controls and commands are in [README.md](README.md).

The reading cursor is not a text selection for copying.
Search, copying, a file picker, context expansion, direct two-file/Git inputs, and watch mode are not implemented.
Horizontal mouse/trackpad scrolling is not implemented. Vertical wheel events move three display rows.
Actual trackpad feel and rapid real-window resizing still need Ghostty inspection.

## How the implementation fits together

The source and display paths have separate responsibilities:

1. The input path checks complete file-patch units through libgit2.
2. A private temporary file retains exact patch bytes. Compact in-memory indexes locate files, hunks, source records, and display rows.
3. The application retains the reading position independently of terminal coordinates.
4. The geometry cache maps safe display text to terminal columns and wrapped segments.
5. Ratatui draws the visible cells. The input loop remains separate from syntax work.
6. One syntax worker supplies colors and emphasis. It keeps separate old/new state and coalesces pending viewport requests.

Text can appear before syntax colors. The status distinguishes loading, pending highlighting, and plain-styling fallback.
Missing patch context stays unknown. A distant syntax request parses supplied predecessors rather than inventing a starting state.

Source bytes remain on disk, but source and display indexes remain in memory.
The current file also needs temporary parsing data during conversion.
Split and unified layouts now share context, replacement, and structural blocks. Checked compact spans retain source offsets/lengths and final-newline flags. The input path no longer constructs complete per-line row/location vectors before publication.
The implementation therefore does not use constant memory regardless of input size.
