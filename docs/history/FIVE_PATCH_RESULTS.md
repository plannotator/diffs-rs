# Five-patch acceptance results

Run date: 2026-09-11

This report records the completed batch defined in [FIVE_PATCH_ACCEPTANCE.md](../../FIVE_PATCH_ACCEPTANCE.md).
It used the current release executable through a real PTY on the local M5 Max Mac. Files were warm and fixed. The baseline was 160×50, split, dark, truecolor, with line numbers and wrapping off.

## Independent interior presentation

Each patch completed a real-process rehearsal. The independent checker derived source rows, numbers, signs, hunk boundaries, file headers, wrapping, and layout expectations from the supplied patch reference. It did not import the viewer parser or pairing code.

| Bun | 204 | 435,225 | 1,039,307 | 17 | 303 | pass |

The rehearsal includes opening, forward and reverse movement, endpoints, file and hunk interiors, split/unified layouts, narrower geometry, and resize states. The oracle checked 205 unchanged screens per patch (opening plus 204 states). Deliberate source, number, sign, blank-row, layout, active-side, syntax-color, background, and hunk-header corruptions were rejected for every patch.

This establishes correct emitted terminal cells for the covered states. It does not establish every possible interior screen, every changed-word span, or Ghostty pixel output.

## Sustained memory

Each patch completed one measured process with three tours. Every tour revisited file quantiles and structural extremes, changed layouts, resized, traversed long wrapped lines, and ended with source, wrap, layout, and header resets. Settled RSS is the maximum from the third tour's one-second holds. The target is 128 MiB steady / 192 MiB OS peak for the four smaller patches and 512 MiB steady / 768 MiB peak for Linux.

| --- | ---: | ---: | ---: | ---: | --- |
| Pierre | 244.3 MiB | 303.2 MiB | 303.3 MiB | 303.4 MiB | fail |
| Ghostty | 121.7 MiB | 123.1 MiB | 123.7 MiB | 123.7 MiB | pass |
| Node | 289.4 MiB | 299.0 MiB | 300.6 MiB | 300.6 MiB | fail |

All memory runs completed and exited cleanly. The results show retained growth across repeated tours for four patches. Cache payload limits are therefore not total-memory guarantees; document indexes, parser state, allocator overhead, and active representations remain in the process RSS.

## Evidence and reproducibility

The raw rehearsal traces, frozen manifests, repeat JSON, PTY tails, oracle results, and logs are in the temporary run directory recorded in the final verification report. The aggregate is generated by `tools/aggregate_five_patch_report.py`.

The report intentionally does not claim actual Ghostty screenshot or paint-time acceptance. PTY timing ends at observed terminal output and cannot measure emulator frame delivery. This batch does not compare competing viewers.

The current result is not a full release acceptance: interior source correctness passes, latency has one strict outlier, and memory targets fail on four patches. The next engineering step is to reduce retained representation/index memory and investigate the Pierre distant styled-seek outlier, then rerun this exact frozen workload.
